# AI 辅助网文创作流程 · 调研

> 调研时间：2026-10-08
> 说明：本文档是流程调研，不是教程。所有事实尽量标注来源与可信度。
> 可信度标记：【官方】平台/行业协会正式规则 ｜【实操】作者实操经验帖 ｜【传言】社群说法，未经证实 ｜【常识】长期行业共识

## 0. 先看这一页：你现在的处境

你的情况：想写网文，完全没选题想法。

**不要先纠结写什么。** 正确顺序是：

1. 先定**平台 + 频道 + 目标**（决定节奏、字数、审核口径）
2. 再用「约束条件 + 批量候选」逼出选题（不是苦想）
3. 用 200 字小样试手感，选出你写得动的那个
4. 然后才进大纲流程

第 1、2 步大概 1-2 天能做完，比你想的快。

## 1. 从 0 到发书的完整流程

网文（尤其长篇连载）的行业共识是**分层大纲 + 滚动推进**，不是一次性写完大纲再动笔。

```
选题定位 → 一句话卖点 → 人物小传 → 力量/世界观设定
   → 总纲（全书终极目标）
   → 分卷纲（每卷 50-80 章的目标）
   → 细纲（前期 20-60 章的节点）
   → 章纲（下一章：开局状态 / 核心事件 / 结尾钩子）
   → 正文（AI 初稿 + 人工改稿）
   → 润色去 AI 味 → 发布 → 看数据 → 回调节奏
```

### 1.1 各阶段：人做什么 / AI 做什么 / 产出物

| 阶段 | 人（必须自己做） | AI（适合承担） | 产出物 |
|---|---|---|---|
| **选题定位** | 决定频道、题材边界、自己的兴趣与知识储备 | 批量生成候选创意、拆解爆款卖点 | 3-5 个候选方向 |
| **一句话卖点** | 拍板选哪个 | 压缩/改写成一句话梗概 | 一句话 logline |
| **人物小传** | 定核心欲望、核心恐惧、性格矛盾 | 扩写背景、口头禅、关系网 | 主角卡 + 3-5 配角卡 |
| **世界观** | 划定"哪些设定真的影响剧情" | 生成力量体系、地图、势力 | 精简设定表（不超过 2000 字） |
| **总纲** | 定终极目标与结局走向 | 给出 2-3 种结局方案 | 全书 5-10 行 |
| **分卷纲** | 定每卷的情绪曲线与大事件 | 拆节点、埋伏笔建议 | 每卷 300-500 字 |
| **细纲** | 定节奏、砍掉水分情节 | 展开前期 20-60 章节点 | 每 5-10 章一个节点卡 |
| **章纲** | 决定这章"留什么钩子" | 生成初版三要素 | 开局/事件/钩子 三行 |
| **正文** | **掌握方向盘**：剧情走向、情绪、对话 | 出 800 字梗概 → 1500-2000 字初稿 | 章节初稿 |
| **改稿** | 通读定走向，再逐句改语感 | 检查逻辑矛盾、伏笔回收 | 成稿 |
| **发布** | 看后台数据、决定是否回调 | 分析完读率下滑原因 | 更新 + 运营笔记 |

### 1.2 大纲为什么分层【实操】

- 一次性让 AI 生成"全书完整大纲"没有意义——写到 20 万字时一定会被改得面目全非。
- 行业做法是**滚动式大纲**：只把「全书终极目标 + 当前卷」定死，写完这卷再规划下一卷。
- 章纲不必每章都细到爆。只要三个要素：
  1. **开局状态**（主角现在卡在哪）
  2. **核心事件**（这章必须发生什么）
  3. **结尾钩子**（读者为什么点开下一章）

> 来源：CSDN《DeepSeek+番茄小说：AI辅助网文创作全流程实操指南》（2026-09-15，[csdn](https://blog.csdn.net/)）；微信公众号「网络作家时代书写」「阿慢慢的网文日记」「漫游的织稿匠」等大纲方法帖。【实操】

## 2. 平台规则与风险（这块最要紧）

### 2.1 行业公约【官方】

2025-04-29，中国音数协联合**阅文、咪咕、番茄、晋江、掌阅、点众、中文在线、七猫、纵横、联通沃悦读、磨铁、盐言故事、趣阅、连尚、长江、书旗**等 16 家平台发布《网络文学行业反洗稿自律公约》：

- 明确反对任何洗稿行为
- **要求各平台建立 AI 辅助创作使用规范**
- 成立"网络文学行业反洗稿联盟"，统一反洗稿认定流程

> 来源：TechWeb / 腾讯新闻，2025-04-29（[view.inews.qq.com](https://view.inews.qq.com/a/20250429A0781A00)）

### 2.2 晋江：目前最明确的官方 AI 规定【官方】

2025-02，晋江站长 iceheart 发布《关于AI辅助写作使用、判定的试行公告》，**首次**给出官方口径：

**只允许三个级别使用 AI：**
1. 文字型辅助 —— 校对
2. 创意型辅助 —— 要素
3. 创意型辅助 —— 粗纲

超出上述范围即认定影响原创性，禁止使用。

**违规处罚：**
- 锁章
- 黄牌一个月
- **永久禁榜**（含人工榜和自然榜）
- VIP 章节：退还该章全部订阅收入，且必须**回退到使用 AI 前的原始稿件**才能解锁

> 来源：站长之家转载 AIbase，2025-02-19（[chinaz.com](https://www.chinaz.com/)）

**翻译成人话**：晋江等于把"AI 可以帮你出粗纲、给要素、做校对，但**不能替你写正文**"写进了规则。想在晋江写，就按这个边界来。

### 2.3 起点 / 阅文：红线是「非真人 + 自动化」【官方】

2026-04-21 起点《关于进一步加强对非真人自动化创作管理力度的公告》：

- **红线是「非真人」+「自动化」的组合**，不是「用没用 AI」
- 明确区分：
  - **AI 辅助**（大纲 / 校对 / 润色）→ **允许**
  - **AI 全篇生成** → **零容忍**
- 官方提供「**阅文妙笔**」供签约作者辅助使用（说明平台自己也在推合规工具）
- 技术检测力度在各平台中最严

> 来源：五平台合规综述（CSDN edtoplort，2026-10）；合规篇（loopne，2026）

**这条对你最重要**：你「AI 构思 + 自己写初稿 + AI 校对」的分工，**正好落在「AI 辅助」这一侧**，是被允许的用法。

### 2.4 番茄：明禁暗许，重点打水文【实操 + 官方】

- 官方口径：禁止 AI 生成正文
- **实际执法重点是「批量低质水文」**：2026-02 点名滥用 AI 批量创作，**梯度处置 855 个账号**
- 同时内置「**番茄作家助手**」（豆包驱动）给作者用
- 对「AI 辅助 + 人工精修」的高质量内容实际默许
- 行为异常本身是高危信号：日更 4 万字、一次开 10 本书、机械定时更新

> 来源：番茄作家专区；loopne《60分天花板》合规篇

### 2.5 其他平台

| 平台 | 态度 | 说明 |
|---|---|---|
| **七猫 / 飞卢** | 较宽松 | 政策模糊，主要看内容质量；七猫有产量需求；低质水文同样清 |
| **微信** | 收紧 | 反对「非真人自动化创作」（AI 生成 + 自动发布 + 传播教程） |
| **小红书** | 收紧 | AI 参与内容需**主动标识** |

### 2.6 平台到底怎么检测 AI？【实操共识】

**核心结论：平台查的不是「是不是 AI 写的」，是「是不是低质水文」。**

| 手段 | 看什么 |
|---|---|
| **行为异常** | 日更 4 万字、一次开 10 本书、批量注册、机械定时更新 |
| **内容质量** | 重复、套路化、无细节、AI 腔 |
| **文本特征** | 困惑度（Perplexity）低、突发性（Burstiness）不足——AI「太顺」、句子长度均匀 |
| **创作轨迹** | 有无大纲演进、修改记录（晋江甚至可能要求创作过程证明） |

**纯技术检测不可靠**：GPTZero 等对改写文本失效；人类名作（老舍《林海》）曾被误判 99% AI。**多位作者反映误判风险**。

**待核实传言**：2026-08 起点对均订过万 AI 小说集中清榜、"AI 占比超 10% 就下榜"——**未见官方原文，勿当定论**。

### 2.7 版权归属（有判例了）【司法】

| 判例 | 情形 | 结论 |
|---|---|---|
| **腾讯 Dreamwriter 案**（2019） | 人组织策划 + 设定模板 + AI 生成 + 人承担责任 | 构成作品，版权归运营方 |
| **「春风送来了温柔」案**（2023，北京互联网法院） | 用户提示词 + 参数调整 + 选择 | 独创性劳动，**版权归用户** |

**实操结论**：
- 一句话让 AI 生成 → 通常**无版权**
- **投入大纲、人设、多轮修改、深度参与 → 可能享有版权**（看「人的独创性投入」）
- AI 不是侵权免责事由；照搬情节/人物/设定即侵权；换名字脱敏不能免责

**签约三注意**：
1. 协议中「原创承诺」要**如实申报 AI 辅助**（有的平台要求）
2. 有的条款可能约定 AI 内容版权归平台，**签前读清楚**
3. **保留大纲、修改记录、手稿**作为创作证据

### 2.8 行业真实状态

「明禁暗许」——阅文系调研称约 **75% 作家在用 AI 辅助**（样本为平台内作者）。平台自己也在推 AI 工具。**真正的红线是「非真人批量低质」，不是「AI 辅助」。**

### 2.9 结论：怎么用才安全

| 做法 | 风险 | 你的情况 |
|---|---|---|
| **AI 出创意/要素/粗纲，人写正文，AI 校对** | **低** | **← 你的计划，正好是合规最优解** |
| AI 出初稿，人改 60% 以上，保留改稿证据 | 中 | 行业主流做法 |
| AI 直出正文发布、不改稿 | **高** | 封号 + 不签约 + 无版权 |
| 批量洗稿、AI 改写他人作品 | **极高** | 行业公约重点打击 |

## 2A. 质量天花板：一个重要的行业数据

来自 loopne《60 分天花板》27 款工具横测（2026-08，系统性调研）：

| 模式 | 质量上限 |
|---|---|
| AI 全自动生成 | **约 60 分** |
| 人机协作 | 65–75 分 |
| 合格网文（可发可签约） | **约 80 分** |

- **未发现能稳定「一键出可发稿」的工具**
- 职业主流是「**AI 初稿 + 人工改 60%**」
- 四大嵌套瓶颈：**长篇一致性**（50 章+ 人设崩塌几乎不可避免）→ 创意平庸 → 情绪假 → 质量评估空白
- **10 章内基本能维持；20 章开始人物工具化；50 章以上必然崩**

**对你的意义**：你自己写初稿，比行业主流还保守一档——**质量上限更高，且不会踩任何红线**。代价是慢，但第一本书的目标是完本，不是爆火。

## 3. 「没想法」怎么办：选题方法

### 3.1 别问"我该写什么"，要给约束条件【实操】

直接问 AI"我该写什么"会得到一堆正确的废话。正确做法是**先给约束，再要候选**：

```
我在【番茄小说】写书，想主打【都市脑洞 / 系统流】。
自己有【三年互联网运营】经验，生活中见过不少职场奇葩事。
希望开篇能快速抓住读者，节奏要快，爽点要密。

请列出 8 个适合这个定位的具体故事创意，每个包含：
1. 一句话梗概
2. 核心冲突
3. 为什么番茄读者会喜欢它
4. 最大的扑街风险点
```

然后**用排除法选**：
1. 删掉完全没感觉的
2. 删掉明显驾驭不了的（比如完全不懂的硬科幻）
3. 剩下 2-3 个，每个写 **200 字小样**，找手感
4. 手感最好的那个开写

> 光靠脑子想体会不到文字手感，一定要落到纸上。

### 3.2 常见的选题杠杆

1. **扒榜**：看目标平台近期新书榜、完读率高的书。"你以为的好书可能是五年前的"——**用榜单指导选题，别凭感觉**【实操】
2. **金手指要显性化**：编辑需要**明确看到**主角的金手指。"隐藏金手指 = 扑街预兆"【实操】
3. **职业/经历做底**：把你自己的行业、城市、专业变成信息差。这是 AI 帮不上的部分，也是你最容易写得真的部分
4. **品类组合**：题材 × 金手指 × 情感关系 × 时代背景，四格里各挑一个做碰撞
5. **一句话卖点必须能说出口**：如果说不出一句话，说明核心还没聚焦

### 3.3 平台节奏差异【实操】

| | 番茄（免费+广告） | 起点（付费） | 知乎盐选（短篇） |
|---|---|---|---|
| 章节字数 | 约 1000-2000 | 约 2000-3000 | 2-5 万字成篇 |
| 开篇要求 | **三章定生死**，前 500 字要钩子 | 黄金三章，可稍慢 | 强反转、强悬念 |
| 节奏 | 压抑-铺垫-爆发，1 小爽点/章 | 爽点可稍疏 | 密集爆点 |
| 新人友好度 | 高（流量扶持、签约易） | 中低 | 中（回款快） |
| 核心数据 | 完读率、书架转化、追读 | 订阅、月票 | 过稿率 |

**番茄新书期常见数据门槛**（社群经验，会随平台政策变动）：
- 完读率 ≥ 15-30%
- 追读率 / 书架比 ≥ 30-35%
- 前 3 章淘汰率极高，"文笔好但水三章的，不如文笔烂但三章死五个人的"【传言】

## 4. 人机协作：怎么做才不像 AI

### 4.1 核心原则【实操共识】

> **AI 是"资深编辑 + 高速初稿机"，不是"打字机"。**
>
> 你负责"什么值得写、情绪怎么推、细节怎么落"，AI 负责批量出选项、查一致性、扛体力活。

### 4.2 正文工作流（最常被验证的一套）

1. **给细纲节点** → AI 写 800 字本章核心剧情梗概
2. **人看梗概**，确认方向没跑偏
3. AI 扩写成 **1500-2000 字初稿**
4. **人先通读定走向**（AI 经常自己脑补剧情，妙的留下，跑偏的删掉）
5. 最后**逐句改语感、改情绪、改对话**

关键：**你始终掌握方向盘**。既不用从空白页开始，也不会被 AI 带走。

### 4.3 去 AI 味的三板斧

1. **喂文风样本**：挑 2-3 段你自己满意的文字，贴进对话，声明"之后所有续写严格模仿这个语感"。每次续写都重申一次
2. **禁用词清单**：`不禁`、`终于`、`仿佛`、`命运`、`或许`、`岁月`、`眼中闪过一丝`……遇到就删
3. **强制短句**：在提示词里写"所有句子不超过 20 字，多用动作与心理，少用环境描写"

另外：**AI 味集中在段落首尾的连接句**，核心事件描写往往还行。通读时圈出不舒服的地方，一起处理连接句，整章风格就正了。

> AI 对"润色"的默认理解是"统一风格、降低风险"，这恰恰会杀死个性。不要让它"润一遍"，要给它明确的风格约束。【实操】

### 4.4 长篇崩文防线

- **逻辑校对**：把人物卡 + 重要事件表丢给 AI，让它查最新章节与前文的一致性
- **伏笔盘点**（每 30 章一次）：
  ```
  这是本书前 30 章的主要剧情线和出场人物表。
  请梳理：还有哪些伏笔没回收？哪些人物关系前后矛盾？哪些时间线对不上？
  生成一个待处理清单。
  ```
- **数据回调**：把完读率、追读变化告诉 AI，让它分析节奏问题

### 4.5 五种最常见的翻车

| 翻车 | 表现 | 对策 |
|---|---|---|
| 同质化 | 全是"震惊！""竟然！"，设定撞车 | 从你的职业/城市找信息差；每次生成要 3 个不同方向 |
| AI 味 | 每句都对，连起来假大空 | 文风样本 + 禁用词 + 短句 |
| 设定崩塌 | 第 10 章写活了第 3 章死掉的人 | 人物卡常驻上下文 + 伏笔盘点 |
| 节奏失控 | 5 万字还在铺垫 | 节点目标制：每 5-10 章必须达成一个剧情目标 |
| 更新压力 | 日更跟不上，断更=前功尽弃 | 留 5-10 章存稿再发；用 AI 扛初稿，人只做改稿 |

## 5. 工具形态

### 5.1 通用大模型

| 工具 | 适配点 | 说明 |
|---|---|---|
| **DeepSeek** | 中文语感、长上下文、成本极低 | 实操帖里最常被推荐给新人起步 |
| **Claude / GPT** | 复杂推理、长文一致性、改稿 | 适合做逻辑校对、伏笔盘点、审查清单 |
| **豆包** | 角色对话、灵感发散、口语化 | 网文语感不错；番茄作家助手底层即豆包 |
| **文心一言 / Kimi** | 古风描写、长文拆解 | 文心适合过审；Kimi 适合长上下文拆书 |

**新人建议**：先用低成本工具把提示词和流程跑顺，**别让工具绑架创作**。等稳定签约、日更压力大了，再考虑自动化。

### 5.2 平台官方工具（优先用，合规无风险）

| 工具 | 归属 | 用途 | 备注 |
|---|---|---|---|
| **阅文妙笔** | 起点官方 | 大纲 / 校对 / 润色 | 供签约作者使用，用它=合规 |
| **番茄作家助手** | 番茄官方 | 灵感、卡文、取名、查资料 | 豆包驱动，**编辑器内直接用** |
| **阅文作家助手** | 阅文 | 大纲设定管理 | 全平台覆盖 |

**意义**：平台一边打「非真人自动化」，一边自己发辅助工具——**用官方工具辅助构思和校对，是最不会被误伤的路径**。

### 5.3 垂直工具 / 开源工具链

| 类型 | 代表 | 适配 |
|---|---|---|
| **垂直写作站** | 笔灵、蛙蛙写作、FeelFish、唐库 | 建书→设定→大纲→成稿一条龙 |
| **海外** | Sudowrite、Novelcrafter | 结构化强，中文网文语感弱 |
| **开源 Claude Code skills** | [oh-story-claudecode](https://github.com/zenstory-ai/oh-story-claudecode)（7.3k★） | 扫榜→拆文→大纲→去AI味 全流程 |
| **开源模板库** | [chinese-novelist-skill](https://github.com/PenglongHuang/chinese-novelist-skill)（3.3k★） | 大纲/人物/章节模板最全 |
| **多 Agent 质量门** | [awesome-novel-agent](https://github.com/modoojunko/awesome-novel-agent) | 写作-审-改循环 |
| **三级大纲** | [QMAI](https://github.com/Mochocyang/QMAI) | 灵魂/风格文档思路 |

**对你现阶段的建议**：**不用装任何工具**。这个仓库里的 [提示词库.md](提示词库.md) 已经把开源项目里最有用的模板抽出来了，直接用就行。等写到 20 万字以上再考虑上工具链。

### 5.3 设定库 / 记忆管理（长篇刚需）

起步阶段**不需要**复杂工作流编排。最小可用做法：

```
novel/
├── 00-调研-AI辅助网文创作流程.md   ← 本文件
├── 01-选题候选.md
├── 02-一句话卖点.md
├── 03-人物卡.md          ← 主角 + 配角，常驻喂给 AI
├── 04-世界观.md          ← 只留影响剧情的
├── 05-总纲.md
├── 06-分卷纲.md
├── 07-细纲.md
├── 08-章纲.md            ← 只写下一章
├── 09-伏笔账本.md        ← 埋了什么、何时回收
├── 10-文风样本.md        ← 你自己的代表段落
├── 11-禁用词清单.md
└── chapters/
    ├── 001.md
    └── ...
```

每次写新章，把 **人物卡 + 本卷纲要 + 上一章结尾 + 本章章纲 + 文风样本** 喂给 AI，就够撑起一致性了。

## 6. 可复用提示词模板

### 6.1 选题（填空版）

```
我在【平台名】写书，频道【男频/女频】，主打【题材类型】。
我的背景：【职业/专业/城市/兴趣，3-5 条】
读者画像：【例：番茄免费读者，20-35，要快节奏强爽点】

请给出 8 个具体故事创意，每个包含：
1. 一句话梗概（不超过 40 字）
2. 核心冲突
3. 金手指（必须显性化、可量化）
4. 爽点结构（读者爽在哪）
5. 扑街风险点
6. 与同类热门书的差异点
```

### 6.2 一句话卖点

```
基于以下创意【粘贴】，请给出 5 个不同风格的一句话卖点（logline）：
- 版本A：强调爽感
- 版本B：强调情感
- 版本C：强调设定新奇
- 版本D：强调反差
- 版本E：你自己认为最优的一个
每个不超过 40 字，口语化，能在作者后台简介第一行用。
```

### 6.3 人物小传

```
请为以下角色写人物卡，控制在 300 字内：
角色定位：【主角/女主/反派/导师】
在故事中的功能：【例：提供信息差 / 制造压迫感】
核心欲望：【】
核心恐惧：【】
性格矛盾点：【例：极度自负又极度心软】
要求：给出 3 句标志性口头禅/说话习惯，并说明他绝不会说什么。
```

### 6.4 分卷纲 / 细纲

```
全书核心：【一句话卖点】
全书预计【N】章，第【X】卷写到第【M】章。
本卷目标：主角从【状态A】到【状态B】。

请拆解本卷节奏，每 10 章为一个节点，每个节点写：
1. 节点末尾要达成的剧情目标
2. 需要埋下的伏笔
3. 本阶段情绪高潮落在第几章
4. 章末钩子的方向

不要写大段背景历史，只要能直接落到正文的东西。
```

### 6.5 章纲

```
【粘贴：人物卡关键信息 + 本卷节点要求 + 上一章结尾 300 字】

请写本章章纲，只给三要素，每项不超过 50 字：
1. 开局状态
2. 核心事件
3. 结尾钩子

额外要求：本章必须包含【某个伏笔/某个爽点】，不要跳到反派视角。
```

### 6.6 正文初稿

```
【粘贴：文风样本 + 章纲 + 上一章结尾 500 字】

请严格按照文风样本的句式长度、用词习惯、对话风格写作。
硬性约束：
- 所有句子不超过 20 字
- 多用动作描写和心理活动，少用环境描写
- 禁用词：不禁、终于、仿佛、命运、或许、岁月
- 主视角全程跟随主角，不跳反派视角
- 章末必须落在钩子上，不要总结式收尾

先输出 800 字本章剧情梗概，我确认后再扩写成 1800 字正文。
```

### 6.7 逻辑校对 / 伏笔盘点

```
以下是本书的人物卡与重要事件时间线：
【粘贴】

以下是最新一章：
【粘贴】

请检查：
1. 与前文设定有无矛盾（人物生死、名字、能力、时间线）
2. 有哪些伏笔尚未回收
3. 本章有无 AI 味集中的连接句（请标出具体句子）

输出一个待处理清单，按严重程度排序。
```

### 6.8 去 AI 味改写

```
请改写下面这段，目标是"人味"：
【粘贴】

要求：
- 删除所有空话、套话、总结句
- 保留情绪与具体细节
- 句子长短交错，允许不完整句
- 不要"润色"，不要统一风格，要保留毛边
- 特别处理段落首尾的连接句，改成口语化的自然过渡
```

## 7. 与其他写作法的关系

| 方法 | 做法 | 适配网文程度 |
|---|---|---|
| **雪花写作法** | 一句话→一段→一页→大纲→初稿 | ★★★★★ 天然适配分层大纲 |
| **分层大纲法** | 总纲→分卷→细纲→章纲 | ★★★★★ 网文本土主流做法 |
| **按章反馈迭代** | 写完看数据，按完读率回调 | ★★★★★ 网文特有，必须做 |
| **意识流/纯即兴** | 不写大纲直接写 | ★☆☆☆☆ 长篇必崩，短篇可试 |

**推荐组合**：雪花写作法做前期骨架 + 分层大纲做推进 + 按章数据迭代做回调，全程 AI 当编辑和初稿机。

## 关键补充（来自开源项目调研）

详细内容已整合到 [提示词库.md](提示词库.md)，此处只记要点：

1. **选题要做「四步决策」**：能爆的原因（当假设）→ 市场验证（看重复样本，不是单本）→ 差异化定位 → 可行性+验证动作。**没有榜单数据一律只给「中」**。
2. **金手指三类内核**：信息挂（最优，不易失控）> 加速升级挂 > 物体/系统挂（易失控）。**最佳曲线是「刚好解决当前矛盾 → 暴露更大矛盾」**。
3. **每章硬规则**：收一个、变一个、开一个；必须有情绪变化；「既无期待也无爽 = 断期待 = 弃书」。
4. **去 AI 味是「改味不是改错」**：只改怎么说，不改说什么；删除上限 15-35%；三遍法（去泛化→去书面化→回自然感）。
5. **防同质化的关键是文风基准文件**（600-1000 字自己的代表段落）+ 角色语言 7 维差异化 + 模仿结构不模仿文辞。
6. **现成工具链**：oh-story（扫榜→拆文→写作→去AI味 全流程）、chinese-novelist-skill（模板全）、awesome-novel-agent（多 Agent 质量门）。比手工拼 prompt 更稳。
